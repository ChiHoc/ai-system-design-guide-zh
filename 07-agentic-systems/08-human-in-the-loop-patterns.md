# 人类在环模式（Human-in-the-Loop Patterns）

没有任何 agent 是 100% 可靠的。**Human-in-the-Loop（HITL，人类在环）** 是在高风险环境中确保安全性和准确性的桥梁。生产级技术栈已经超越了“Approval Buttons（审批按钮）”，转向 **Co-Reasoning（共推理）** 和 **Interrupt-Based Steering（基于中断的引导）**，并在 LangGraph（interrupt+resume）和 Microsoft Agent Framework 等框架中原生暴露。2026 年更大的转变是**策略门控自治**：分类器或规则引擎决定哪些动作可以执行、哪些要拒绝、哪些要暂停等待人类审批，使人们只需审查少数关键调用，而不必逐项点击批准。

## HITL 频谱

| 模式 | Agent 自主性 | 人类角色 | 最适合用于 |
|---------|---------------|------------|----------|
| **Human-in-command（人类主导）** | 低 | 驱动每一步 | 高风险法律/医疗 |
| **Human-as-filter（人类过滤器）** | 中 | 批准/编辑最终输出 | 内容生成 |
| **Human-as-backup（人类备用）** | 高 | 仅在出错时介入 | 客户支持 |
| **Human-on-the-loop（人在回路外监督）** | 最高 | 任务完成后审计日志 | 高吞吐分析 |

## 中断与断点

现代架构（LangGraph、Microsoft Agent Framework）使用 **Deterministic Breakpoints（确定性断点）**。

- **模式**：系统被硬编码为在调用某个特定敏感工具之前“暂停”，例如 `execute_purchase` 或 `delete_user`。
- **决策**：环境等待用户发送 `approve` 或 `reject` 信号。
- **状态保留**：agent 的推理状态会在数据库中“冻结”，直到人类介入。要跨重启和部署保留暂停状态，应使用持久化工作流（参见[持久化执行](11-durable-execution.md)）；对于 MCP 工具调用内的审批，2026-07-28 的无状态修订会返回 `input_required`，并在客户端重试时恢复执行（参见[工具使用与 MCP](03-tool-use-and-mcp.md#多轮往返请求-mrtr)）。
- **门控动作，而非整个轮次**：模型如今会在一轮中发出多个动作（Claude 的 computer-use 工具集会按顺序执行一个批次，并在首次失败时停止），因此一次模型往返就可能完成多步且影响重大的操作。如果整体批准批次，就等于批准了尚未检查的步骤。应在动作到达时逐一检查，并在每个重大动作执行前确认，即使它位于批次中间；Anthropic 的 computer-use 文档也要求在每个动作块运行前检查。拒绝一个动作后应结束整个批次，将剩余动作标为未执行，让模型从已知状态重新规划。

## 策略门控自治

逐项审批难以扩展，而证据表明人类在实际审查时也是薄弱的过滤环节：Anthropic 在一项对 1,053 名付费测试者的盲测中发现，人类发现被替换进去的危险命令的比例为 13.6%，而 auto-mode 分类器阻止了其中的 89%。Anthropic 于 2026 年 8 月 14 日将基于分类器的 auto mode 设为 Claude Code Pro、Max 和 Team 方案的默认模式时引用了这项研究。各供应商正从“每次都问”转向“由策略决定，人类只看例外”：

| 产品（2026） | 门控方式 |
|---|---|
| **Claude Managed Agents** 自动权限策略（9 月 10 日） | 服务端评估每次 agent 或 MCP 工具调用，决定执行、拒绝或暂停等待审批；结果出现在事件的 `evaluation` 字段中，`ant beta:sessions connect` 可连接终端实时审批 |
| **Claude Code** auto mode | 服务端分类器；自 2.1.284（9 月 28 日）起，未配置权限模式的交互会话默认进入 auto mode |
| **OpenAI dots**（9 月 29 日发布） | 内置规则与 Custom Rules 可针对每个动作设置允许、阻止或要求审批；可能影响账户或共享信息的动作会自动进入审查；空闲时，dot 只能进行只读研究 |
| **OpenAI Agents API** computer use（9 月 29 日） | 每个新网站来源都需要明确的 `browser_origin_access` 审批（启用网络访问并不等于批准）；登录通过单独的界面完成，凭据不会进入模型输入 |
| **GitHub Copilot** computer use（10 月 1 日公开预览） | 按应用审批，永久授权可审查、可重置，并提供组织级停用开关 |

一个相关的基础能力是**决策模型**：它为一组固定答案评分，而不是生成文本，正适合门控场景。OpenAI 的 Decisions API（9 月 29 日限量预览）使用 Luna 模型来分类输入、路由请求或选择 agent 动作；Cloudflare 的 Clef（10 月 1 日发布，Apache 2.0）返回预设答案的概率，供系统决定执行还是暂缓。其基于 Qwen3.8-27B 的版本中位延迟为 209 ms，Clef-flash 为 39 ms。Cloudflare 所称“不再需要人类在环”是供应商主张；更稳妥的用法是让它作为人类审批前的低成本第一道门。

**AI 审批现在也能满足人类审批门槛。** 自 2026 年 9 月 1 日起，Copilot code review 提交的审批可计入仓库的必需审批规则（公开预览、默认关闭、按文件路径限定范围，且像人类审批一样会在新提交后失效）。如果变更也是由 agent 编写，再允许另一个模型的审批满足分支保护，两人规则就会变成无人参与的规则。涉及身份认证、支付、基础设施和 agent 自身配置的路径应保留至少一名人类审批者；只有错误合并容易回滚时，才让 AI 审批计数。

**必须说明的限制**：权限分类器是便利层，不是隔离边界。Johann Rehberger 于 2026 年 8 月展示 auto-mode 绕过时，一条“混淆环境”攻击链在小样本的 5 次运行中成功了 3 或 4 次。据他的报告，Anthropic 回应称 auto mode 是依赖尽力而为分类器的便利功能，而非安全保证；真正的边界是操作系统隔离和网络出口控制。每道策略门都应配合[智能体安全](09-agentic-security-and-sandboxing.md)中的沙箱措施。

## 审批洗白

人类审批是否有效，取决于他们看到的内容与实际执行动作之间能否可靠绑定。2026 年 9 月的一篇论文（arXiv 2609.38983）将**审批洗白**定义为：编程 agent 执行框架实际执行的动作不同于人类批准的动作。论文列出六类情况（范围、参数、时间、工具、委托、语义），并在 Claude Code 的 `PreToolUse` 审批点测量。研究对 118 次运行进行配对重放，发现加密审批令牌消除了委托类和论文植入的时间类洗白，但按设计无法覆盖范围类洗白，对参数类洗白也没有显著改善，因为这些偏差发生在字段级验证器能够观察的层级之下。

应采取的措施：

- **将审批绑定到准确、规范化的动作**（工具、参数、目标、会话），使用哈希或签名令牌，并在执行时重新验证。
- **向人类展示实际执行的形式**，而非模型对动作的描述。
- **让审批快速过期**，并限定于一个会话及一个 agent 身份，防止子 agent 重放。
- **保留沙箱。** 即使审批经过签名仍有盲区，因此审批只能降低风险，无法取代隔离。

## 时间旅行调试（状态编辑）

标准 agent 是“单向”的。如果它在第 3 步犯错，整个会话通常就被毁了。
- **创新点**：**State Injection（状态注入）**。人类审阅者可以“回到”第 3 步的状态，编辑 agent 的 observation 或 thought，然后“恢复”执行。
- **影响**：它让人类无需从零开始，就能把 agent 从错误路径上“引回正轨”。
- **编辑 observation 和计划，不要编辑 thinking。** 在最新的 Claude 模型中，thinking 块与产生它的模型及对话绑定；若请求中先前的 thinking 与前缀不再匹配，请求可能被拒绝。应回退到检查点，编辑 observation 或书面计划，并丢弃编辑点之后产生的 thinking，而不是改写它。

## 共推理（共享草稿区）

人类不再是“Judge（裁判）”，而是成为 **“Partner（伙伴）”**。
- agent 会把自己的 **Scratchpad（草稿区）**（内部思考）展示给人类。
- 其典型表述为：*“我计划因为 Fact B 而使用 Tool A。你觉得这样对吗？”*
- **收益**：在推理错误转化为动作之前就把它捕捉出来。
- **共享计划，而非原始 thinking。** 前沿 API 不再直接返回原始思维链：OpenAI 返回推理摘要；在最新 Claude 模型上，thinking 块默认采用 `display: "omitted"`，除非选择返回文本的显示模式，否则内容为空。让 agent 写出明确的计划和理由供人类审查，并将其视为 agent 对自身推理的说明，而非推理过程的逐字记录。
- **把计划放在团队现有的工作位置。** Asana 于 2026 年 9 月 29 日介绍的 agent 会将研究计划和已采取的步骤发布到共享任务中，让任何审阅者都能在运行中评论和引导；只有管理员和编辑者才能将反馈写入 agent 的永久共享记忆。

## 基于置信度的升级机制

我们为每个影响重大的步骤计算一个 **Uncertainty Score（不确定性分数）**。

- 如果该分数超过阈值，agent 会**自动暂停**并向人类操作员发送通知。
- **分数来源已经变化。** token logprobs 正从前沿 API 中消失（GPT-6 Astra 不提供 logprobs、temperature 或 top_p），而模型口述的置信度校准不佳。当前做法是使用独立、经过校准的评分器：决策模型或分类器针对一组固定结果（继续、询问、升级）返回概率，并通过标注案例调整暂缓阈值。
- **示例**：一个 agent 在尝试解决复杂账单争议时意识到用户意图含糊不清。它会停下来并说：*“我并不完全确定该如何处理这个特定的退款案例。请稍等，我去请一位人工专家来看一下。”*
- **升级记录也是产品数据。** Anthropic 于 2026 年 9 月 30 日介绍其运行在 Claude Managed Agents 上的销售线索 agent：每段对话最后会走向结账、简短答复，或转交销售代表，并附上完整对话及转交原因。据 Anthropic 报告（供应商数据），从线索到商机的转化率提高了一倍多，成交时间缩短约五天，需要人工介入的对话占比大致减半。“原因”字段使升级队列成为反馈循环，而非单纯的待办堆积。

## 面试问题

### Q: 你会如何设计一个不会让人类操作员“疲劳”的 HITL 系统？

**优秀回答：**
我们使用 **Threshold Tuning（阈值调优）**。我们不会对每一个动作都请求批准。我们只在以下情况触发 HITL：1）高风险的“Writing（写入）”工具，2）低置信度的推理步骤，或 3）违反业务设定的 “Policy（策略）” 的动作。此外，我们会向人类提供 **Contextual Summary（上下文摘要）**：不展示完整日志，而是根据规范化的实际动作（不是模型对它的描述）生成一句说明 agent 想做什么的 “Diff（差异）”。这把 “Review cognitive load（审核认知负荷）” 从分钟级降到了秒级。2026 年更有效的办法是将常规决策交给策略门控（如 Claude Managed Agents 的自动权限策略、OpenAI dots 的 Custom Rules），使人类只需处理例外。

### Q: HITL 中 “Over-Reliance（过度依赖）” 的风险是什么，你会如何缓解？

**优秀回答：**
过度依赖发生在人类开始在不阅读日志的情况下直接点 “Approve（批准）” 时。这种风险可以测量：在 Anthropic 的盲测中，人类审阅者发现被替换进去的危险命令的比例只有 13.6%。我们通过 **Forced Review Checkpoints（强制复核检查点）** 来缓解，例如要求人类必须至少修改拟议计划中的一个词；或者通过 **Synthetic Error Injections（合成错误注入）** 来缓解，即有意向人类展示一个“错误”计划，1% 的时间如此，以观察他们是否能发现。如果他们通过了这个 “Trap（陷阱）”，就继续；如果失败，就会被标记为需要额外培训。鉴于人类发现问题的比例如此低，对于不可逆动作，我不会把审批作为唯一的控制手段，而会同时使用沙箱和策略门控。

### Q: 你用分类器为 agent 动作设置执行、拒绝或转交人类的门控。如何设置并监控转交阈值？

**优秀回答：**
我把它视为一个代价不对称的、需校准的决策问题。在线下，我给数百个真实动作标注审慎审阅者会做出的决定，检查校准情况（预测值为 0.9 时，正确率是否真为 90%？），并选择错误自动批准的预期代价（按影响范围加权）与人工审查代价相当的阈值。阈值因动作类别而异：只读动作更宽松，写入动作更严格，而不可逆或面向外部的动作无论分数如何都必须转交。在线上，我监控四个信号：转交率（突然上升意味着分布漂移或攻击）、人类对转交项的改判率（如果人类批准了 99% 的转交项，阈值就太严格，审阅者会停止认真阅读）、对自动批准动作的抽样审计（这是发现错误批准的唯一方法），以及门控增加的延迟。每次更换模型或提示词后，我都会重新校准，因为新 agent 模型会改变分类器面对的动作分布。我也绝不会把分类器描述为安全边界；Anthropic 曾将自家的 auto-mode 分类器描述为尽力而为的便利层，而非安全保证。
