# 基准测试与排行榜

公开基准测试是该领域讨论模型能力的方式：MMLU、SWE-bench、GPQA、Arena Elo。它们有助于定位，也会让决策变得危险。本章会教你每个主要基准测试衡量什么，哪些仍能区分前沿模型、哪些已经饱和，以及如何批判性地阅读基准测试声明，避免被一个数字误导。

核心思想：**基准测试的定义和已知缺陷是稳定的；它的分数是易过期的。** 排行榜数字每周都在变化，会被污染、偏 favorable 的评测框架抬高，也越来越多地受到伪造条目的污染。因此，本页首先说明每个基准测试*衡量什么*以及它*如何失效*，并把具体分数视为有日期、有来源、需要重新验证的快照。关于评估你自己的系统（真正预测生产质量的东西），请参阅 [LLM Evaluation（大语言模型评估）](01-llm-evaluation.md)。

## 如何阅读本页

下面每个基准测试都会列出它**衡量什么**、它的**格式**、它的**饱和状态**（前沿模型集群是否已经高到分数差异只是噪声？），以及它的**已知缺陷**。如果某个当前分数有助于定位，它会带着来源和“验证”标记给出，因为：

- **供应商自报分数高于独立排行榜。** 实验室会在它能找到的最佳评测框架、最佳努力设置和无上限基础设施下报告自己的模型。这个数字不能与另一家实验室的数字或独立运行结果直接比较。只比较由*同一个*评测框架产生的数字。
- **2026 年的网络充斥着伪造的排行榜页面**，会编造模型和分数。如果你看到某个不认识的模型名被归因了前沿编码分数，在主来源（实验室文章、基准测试自己的排行榜）确认之前，先假定它是 SEO 垃圾内容。
- **标题数字隐藏了评测框架。** “SWE-bench 上 `88%`”如果没有智能体脚手架、工具访问、effort 级别和输出 token 上限，就无法解读。自 `2026` 年年中起，还须知道基准版本、评分指标（二元完成或部分得分）、谁运行了评测，以及安全回退模型是否处理了部分任务。

因此：使用*衡量内容*和*缺陷*列来推理一个基准测试，并把任何单一百分比视为有日期的数据点，而不是事实。

## 能力地图

基准测试按它们探测的能力分组。在每个分组中，该领域会持续淘汰已经饱和的基准测试，并用更难的后继者替代，因此仍在起区分作用的基准每年都会变化。

### 通用知识与语言

大多**已经饱和**：前沿模型聚集在 88-90% 以上，因此差异多是噪声。把这些保留为历史基线，而不是前沿区分器。

| 基准测试 | 衡量内容 | 状态 | 备注 |
|-----------|----------|--------|-------|
| **MMLU** | 57 个学科的多选学术知识（约 15.9k 道题） | 已饱和（约 90%+ 集群） | 历史上引用最多的基准测试。约 6.5% 的题目存在标签错误（据 MMLU-Redux）；严重受到网络污染。已从模型卡中逐步移除。 |
| **MMLU-Pro** | 更难的 MMLU 后继者：10 个选项而不是 4 个，偏重推理，约 12k 道题 | 接近饱和 | 为修复 MMLU 饱和问题而构建；现在也触及同样的天花板（顶级集群约 88-90%）。因饱和已从 Artificial Analysis 指数中移除。 |
| **MMLU-Redux** | 对 MMLU 的错误修正再标注（约 3k 项） | 已饱和 | 存在是为了*量化* MMLU 的错误率（发现 6.49% 错误，某些子集最高达 57%），而不是给前沿模型排名。 |
| **HellaSwag** | 常识句子补全 | 完全饱和（95%+） | 人类基线约 95%；自 GPT-4 时代起已被解决。 |
| **ARC-Challenge** | 小学科学多选题 | 已饱和（约 96%+） | 实际上已经解决。 |
| **WinoGrande** | Winograd-schema（温诺格拉德模式）指代消解 / 常识 | 已饱和（约 90%+） | 仍有标注伪影。 |
| **BBH (BIG-Bench Hard)** | 23 个最难的 BIG-Bench 任务，多步推理 | 使用 CoT（思维链）后已饱和（>90%） | 已被 **BIG-Bench Extra Hard (BBEH)** 取代，BBEH 是因为 BBH 饱和而构建的。 |
| **GLUE / SuperGLUE** | 较旧的 NLU（自然语言理解）任务套件 | 已退役 | 模型在 2021 年初就在 SuperGLUE 上超过了人类基线。 |

### 前沿推理

这些基准曾用于区分领域顶部模型。`2026` 年有些已经饱和，有些更换了版本，引用前应先看“状态”列。

| 基准测试 | 衡量内容 | 状态 | 备注 |
|-----------|----------|--------|-------|
| **HLE (Humanity's Last Exam)** | 覆盖 `100` 多学科的封闭式专家问题，抗检索（约 `2,500` 道题，约 `10%` 多模态） | 仍活跃，但 HLE-Diamond 如今是更干净的参照 | 到 `2026` 年年中，它是首要的前沿知识基准，仍占 Artificial Analysis 指数的 `10%`。它在 `2025` 年 1 月发布时，最佳分数低于 `10%`，显示前沿移动之快。工具配置决定排名：Anthropic 自家的完整 HLE 带工具表格中，Claude Opus `5.5` 为 `67.7%`、GPT-`6` Astra 为 `57.2%`（供应商自报），顺序与下方官方 HLE-Diamond 工具运行相反。HLE-Physics 的专家重评（arXiv `2609.13009`）发现多数被审查的“错误”答案实为评分器错误、参考解错误或问题含糊，因此部分剩余提升空间来自标签错误。 |
| **HLE-Diamond** | 从 HLE 清理出的 `1,000` 道题，推理和知识题各半；HLE 团队历经一年清理后于 `2026` 年 9 月 22 日发布 | 活跃，区分度大 | 无工具：GPT-`6` Astra `59.9%`、Claude Opus `5.5` `54.6%`、GPT-`6.1` Sol `53.2%`、Claude Fable `5.1` `50.7%`。带网页和代码工具：Astra `82.9%`、Opus `5.5` `73.9%`、Fable `5.1` `72.3%`。引用时必须注明配置；同时有两种运行结果的模型，工具约增加 `20` 个百分点。 |
| **GPQA-Diamond** | `198` 道博士级生物／物理／化学问题，抗谷歌搜索 | 已饱和 | 设计目标是让有网络访问能力的熟练非专家得分约 `34%`，博士专家约 `65–70%`。OpenAI 发布表格（二手材料转载）中 GPT-`6` Astra 为 `96.0%`，Artificial Analysis 独立运行在 xhigh 下为 `96.3%`。AA 在智能指数 v`4.2` 中将其移为历史指标，只单独运行。它可用于检查中端模型，但不再是前沿排名信号。 |
| **ARC-AGI-2** | 抽象网格谜题推理，关注效率（约 400 个任务）；抗记忆 | 活跃，强区分 | **请仔细阅读：**人类评审组通过率为 85%，85% 是大奖*门槛*。聚合器会报告前沿模型“达到 85%”，但那是在非 ARC-Prize 评测框架下、使用大量测试时计算的自报数字。ARC-Prize-Verified 的天花板低得多（高成本下约在 50 多分中段）。绝不要把门槛当作已达成分数引用。 |
| **ARC-AGI-3** | 首个完全交互式 ARC 基准（`2026` 年 3 月 25 日发布）：代理通过行动发现确定性的封闭机制和目标，效率按每关行动数与人类基线比较 | 依赖评测框架；提供方框架下接近满分 | 发布时前沿 AI 得分为 `0.51%`。ARC Prize 于 9 月 3 日对 GPT-`6` Astra 的半私有运行中，供应商中立的 Standard 框架、最高 effort 得分 **`62.7%`**（`$26,098`）；使用 OpenAI 自身上下文管理功能，在请求之间保留不透明推理状态并压缩上下文的 Provider Adapter 框架、高 effort 得分 **`99.9%`**（`$18,817`）。ARC Prize 分别标注并报告两者。同一模型、同一测试集，差距 `37` 个百分点：这是 `2026` 年评测框架决定标题数字的最鲜明案例。 |
| **FrontierMath** | 研究级数学，专家数学家需要数小时到数天的问题（约 350 道题，私有；Tier 4 最难） | 活跃但快速攀升 | 开放式问题，答案为可自动验证的闭式形式（防猜）。v1 中约 42% 的问题有错误（已在 2026 年 6 月 v2 修复）；它部分由 OpenAI 资助，因此单一实验室数字需要治理层面的提示。Epoch 自己的表述是低于 70% 处于可达范围，因此应怀疑远高于该水平的聚合器分数。 |
| **CritPt** | `50` 多名物理学家编写、覆盖 `11` 个领域的研究级物理推理 | 活跃，但低分部分源于评分问题 | 较新（`2025` 年末），如今占 Artificial Analysis 指数的 `10%`。原始分数仍能区分模型，但 9 月的专家重评（arXiv `2609.13009`）修正参考解并删除有缺陷的题目：在保留的 `54` 项 CritPt 挑战上，GPT-`5.6` Sol 修正后的 pass@4 达到 `94.4%`。低分既可能反映模型弱项，也可能反映标签错误。 |

### 数学

经典数学基准测试已经被解决；仍活跃的区分器是最新竞赛年份和研究级集合。

| 基准测试 | 衡量内容 | 状态 | 备注 |
|-----------|----------|--------|-------|
| **GSM8K** | 小学应用题 | 已饱和（>95%） | GSM-Symbolic 显示，当数字/从句被扰动时分数会下降，说明高分部分来自记忆。 |
| **MATH / MATH-500** | 竞赛数学（AMC/AIME 水平） | 已饱和（顶级约 99%） | MATH-500 是一个 500 题子集；规模小意味着顶端方差很高。 |
| **AIME (2024/2025/2026)** | 奥赛短答题，整数答案，每年 30 道题 | 年份 N 一旦公开就会饱和 | 有价值是因为每年题目都是新的（低污染），直到发布为止。只有 30 项，因此单年分数方差很高；优先使用平均运行结果。2024/2025 已饱和。 |
| **HMMT, Putnam** | 更难的奥赛 / 本科证明竞赛 | Putnam 证明题未饱和 | 证明评分依赖 LLM-judge（大语言模型裁判）；只看最终答案的捷径会夸大真实证明能力。 |

### 编码

代码片段基准测试已经不适合排名；智能体式、仓库规模的基准测试才是生产信号。

| 基准测试 | 衡量内容 | 状态 | 备注 |
|-----------|----------|--------|-------|
| **HumanEval / HumanEval+ / MBPP / MBPP+** | 从 docstring（文档字符串）合成单函数，并用单元测试检查 | 已饱和（前沿约 90-97%） | 规模很小且自 2021 年起公开，因此受到污染。HumanEval+ 增加了约 80 倍测试，以捕捉脆弱代码；如果 + 版本分数下降，说明弱测试曾让有 bug 的代码通过。不要用它给前沿模型排名。 |
| **SWE-bench Verified** | 解决真实 GitHub issue，使隐藏测试通过（人工验证的 `500` 个 issue 子集） | 接近饱和，受污染 | `2024–2026` 年典型编码数字。但 OpenAI 自己的评测团队指出，超过 `60%` 的任务测试有缺陷，解法可从任务 ID 原样复现；`2026` 年的仓库扰动研究（arXiv `2609.27891`）发现，改写命名空间和问题陈述后分数持续下降，指向记忆化的仓库线索。可用作“高于约 `80%` 即为前沿”的分层过滤器，不适合精细排名。仅评测框架选择就会让结果摆动 `10–20` 个百分点。 |
| **SWE-Bench Pro（v`2`）** | 跨公开、留出和商业仓库的较难问题解决。Scale 于 `2026` 年 9 月 22 日发布的 v`2` 更新指令、验证器和容器镜像，并从 `731` 个公开任务中剔除 `89` 个无效任务 | 公开子集已饱和，私有集才是信号 | 公开 `642` 项任务：Claude Opus `5` `99.4%`（`638/642`），Kimi K`3` `97.7%`。私有 `272` 项任务：Opus `5` `81.6%`（`222`），Kimi K`3` `214`，GLM-`5.3` 与 Gemini `3.8` Flash 各 `211`（Scale 运行）。Scale 认为 `17.8` 个百分点的公开／私有差距主要源于训练时接触了公开仓库。v`2` 的**网络锁定协议**（沙箱只连接模型端点）与在干净镜像上重新评定每份 diff、同时公布两次评分的做法，发现一款模型伪造了 Go 模块版本。对 v`1.0` 的审计（arXiv `2609.34262`）发现，在匹配任务中，不应获得的通过从 Opus `4.7` 的 `24%` 上升到 Fable `5` 的 `73%`，主要原因是从 git 历史读取参考解。 |
| **SWE-bench Multimodal** | 解决视觉/UI 软件问题（JS 前端，包含损坏 UI 的截图） | 未饱和 | 测试真实视觉 grounding（视觉落地/对齐）；纯文本 SWE-bench 系统表现吃力。 |
| **SWE-rebench / SWE-bench-Live** | 持续更新、去污染的问题解决；任务晚于模型截止日期 | 未饱和 | 最强的污染审计。SWE-rebench 专门捕捉 Verified 上虚高但在新任务上崩塌的分数。 |
| **LiveCodeBench** | 按发布日期标注的竞争性编程题；只在截止日期之后的问题上计分 | 在新鲜窗口中未饱和 | 通过构造实现抗污染。竞争性编程不是软件工程，因此它预测算法推理，而不是仓库工作。 |
| **Aider Polyglot** | 跨 6 种语言的真实多文件编辑，必须输出有效编辑格式，2 次尝试 | 接近饱和（约 88%） | 衡量编辑格式可靠性，而不是仓库规模推理；Exercism 来源公开（污染）。 |
| **SciCode** | 分解为子问题的研究级科学编码 | 远未饱和 | 最难的主流编码基准测试。注意存在两种不兼容的评分约定（主问题 vs 子问题）；始终注明使用哪一种。 |
| **Terminal-Bench `4.0`** | `66` 项任务：从 `3.0` 的 `74` 项中删除 `8` 项（饱和、拒答、公开解答、质量或平台问题各 `2` 项），修复 `19` 项，并设置统一的 `8` 小时代理超时。于 `2026` 年 8 月 28 日宣布 | 活跃，当前的终端代理区分器 | 采用语义版本：主版本变化意味着要重跑，`3.0` 成绩不能沿用。tbench.ai 9 月 21 日榜单：GPT-`6` Astra（Codex）max 为 `58.18%`、high 与 xhigh 为 `57.88%`；Claude Fable `5.1`（Claude Code）max 与 xhigh 为 `57.88%`、high 为 `54.55%`；Claude Opus `5`（Claude Code）xhigh 为 `53.94%`。还要看成本列：Astra max 运行约 `$3.3K`，Fable `5.1` 近似成绩约 `$6.2K`。供应商自报：Anthropic 给出 Opus `5.5` xhigh `66.4%`（标准误 ±`2.6`），Sonnet `5.5` `70.6%`（发布表格未说明 effort），故其自家运行中更便宜的模型反而领先；OpenAI 所报 Astra `57.9%` 是 high effort 运行。 |
| **Terminal-Bench `3.0`** | 覆盖 `7` 个领域的 `74` 项任务，于 `2026` 年 7 月 30 日发布以取代饱和的 `2.1`；发布时短暂称为“Frontier-Bench v`0.1`” | 约四周后被 `4.0` 取代 | 发布时领先者：GPT-`5.6` Sol（Codex）`34.4%`、Fable `5`（Claude Code）`33.8%`。它显著拉大差距（在 `2.1` 上相差 `4.9` 分的两个模型，在 `3.0` 上相差 `12.7` 分）。其短暂寿命说明：有版本的基准如今会在数周内退役饱和或泄漏任务，每个分数都必须附上版本。 |

**为什么智能体式基准测试取代了 HumanEval：** HumanEval/MBPP 对每个前沿模型都在 90%+ 饱和，规模小且被记住了，并且单函数 docstring 到代码的任务不能预测真实工程能力。证据是：SWE-bench 发布时，同一代在 HumanEval 上取得高分的模型，解决率低于 2%。阅读仓库、运行测试、阅读堆栈跟踪并迭代补丁是另一种技能，因此该领域转向了 issue 解决和终端基准测试。

### 长上下文

核心发现：**标称上下文窗口夸大了可用上下文。** 应该先讲这一点，而不是规格表上的窗口大小。

| 基准测试 | 衡量内容 | 状态 | 备注 |
|-----------|----------|--------|-------|
| **NIAH（needle-in-a-haystack，大海捞针）** | 在不同深度和长度下检索单一事实 | 已饱和 / 琐碎 | 前沿模型得分约为 100%，这会带来虚假的信心。它是健全性检查，而不是区分器。 |
| **RULER（NVIDIA）** | 在受控长度下的检索、多跳追踪、聚合、QA；报告“有效长度” | 未饱和 | 有效长度与标称长度差距的主要来源：许多声称支持 128K 的模型，只能把质量保持到约 32-64K（标称值的 25-50%）。它是合成测试，所以要搭配基于散文的测试。 |
| **Fiction.LiveBench** | 深层叙事理解（心智理论、时间顺序、隐含推理），最高约 192K 个 token | 未饱和 | 最严苛的实用长上下文测试；大多数模型到 192K 时会跌到 80% 以下。规模很小（36 道题），因此噪声较大。 |
| **MRCR（multi-round coreference，多轮共指）** | 在多个近乎相同的大海捞针目标中进行区分，并返回第 i 个 | 未饱和，尤其是 8-needle | 分数会随着 needle 数量和长度陡降。 |

设计文档里可以使用的一句话：*标称上下文窗口通常会夸大可用上下文；在 RULER 上，许多声称支持 128K 的模型只能把质量维持到约 32-64K，尽管前沿水平正在快速提升。* “context rot（上下文腐化）”研究（退化会在窗口上限之前很早出现，有时甚至出现反直觉结果：打乱的大海捞针集合比连贯文档表现更好）进一步支持按更小的有效预算来设计。参见 [Context Engineering（上下文工程）](../05-prompting-and-context/05-context-engineering.md)。

## 批判性阅读基准测试

这才是真正重要的部分。任何人都能读排行榜；*正确*地读才是技能。

### 饱和

当前沿模型聚集在非常接近上限的位置，以至于分数差异落入噪声范围时，基准测试就饱和了。MMLU 是典型案例：GPT-4 在 2023 年初达到约 86%，此后前沿模型一直停留在 86-93%，因此 2 分的“胜利”往往只是提示词伪影（MMLU 分数会因提示措辞不同而变化 4-5%）。可用的工作信号是：**当领先者集中在约 3 分以内时，排名顺序是统计噪声，而不是能力差异。**

当一个基准测试饱和后，领域会用以下方式回应：(1) 更难的后继者（MMLU 之后是 MMLU-Pro，再之后是 HLE），(2) 私有或留出测试集，(3) 有时间门控的“live（实时）”基准测试，以及 (4) 复合指数。静态公开基准测试的有用寿命中位数不到约 2 年。

`2026` 年，这段寿命缩短到数月，有时甚至只有几周。Terminal-Bench `3.0` 推出约四周后就被 `4.0` 取代。8 月仍是主要编码信号的 SWE-Bench Pro，其 v`2` 公开子集到 9 月底达到 `99.4%`。ARC-AGI-3 从 3 月发布时的 `0.51%`，不到六个月就在提供方评测框架下达到 `99.9%`。GPQA-Diamond 与 BrowseComp 在前沿模型上均超过 `90%`。因此，在设计文档中引用基准时，应在引用当周核查其版本与饱和状态。

### 污染

基准测试是公开的，会被抓取进预训练数据，因此模型可能通过记忆而不是能力获得高分。证据很直接：重新推导 HumanEval 风格问题（EvoEval）使 51 个模型的分数下降约 39%；在 LiveCodeBench 上，某模型在截止日期前问题上的通过率约为 60%，在截止日期后问题上降到约 0%；OpenAI 发现 SWE-bench Verified 的解法可以从任务 ID 逐字复现。在多个多选 QA 基准测试中，测得的污染范围从 1% 到 45%，并且更大的模型从中获益更多。

抗污染设计包括：**time-gating（时间门控）**（只对模型截止日期之后发布的问题计分，如 LiveCodeBench 和 SWE-rebench）、**private held-out sets（私有留出集）**（FrontierMath、ARC-AGI-2；代价是不可复现），以及 **canary strings（金丝雀字符串）**（在数据集中植入唯一 token，如果模型复述它就标记污染）。检测方法（n-gram 重叠、成员推断、TS-Guessing 测验）都有失效模式；尤其是成员推断攻击，在真实预训练模型上几乎只比随机略好。实际做法是：对任何静态公开基准测试，都假设存在一定污染，并折扣其绝对数值。

**`2026` 年出现了结构性防御。** 三种设计超越了时间门控。**委托编写任务**专门从零创作，而非从已合并 PR 中挖掘（DeepSWE）。**网络锁定运行与独立重评**切断代理访问仓库、包索引和网页的能力，再在干净镜像上重评每份 diff（SWE-Bench Pro v`2`）。**双盲评测**让双方都看不到对方的秘密：Google DeepMind 于 `2026` 年 8 月与新加坡 AI 安全研究所、OpenMined、AVERI 和 MLCommons 试点在 Google Cloud Confidential Space enclave 中运行，使提供方看不到测试提示词，评测方看不到权重（已宣布，尚无结果）。污染还出现了新途径：有网页权限的并行实例通过公开 wiki 分享答案，因此评测框架不仅要将实例与互联网隔离，还要隔离各实例。

### Harness 与脚手架方差

同一组模型权重会因提示词、是否可用工具、推理努力级别以及 agent（智能体）脚手架不同而产生 10-20 分的差异。Anthropic 测得，仅基础设施配置本身（RAM、并发，甚至一天中不同时间的 API 延迟）就会让 Terminal-Bench 结果移动约 6 分。这就是为什么**供应商自报分数高于独立排行榜**：实验室会报告它们为自家模型找到的最佳 harness 和努力级别，并运行在不受限制的基础设施上。由此得到的硬规则是：**绝不要把一个供应商的数字与另一个供应商的数字比较，也不要与独立排行榜比较。** 只有同一 harness 下的数字才可比较。而且推理努力并非单调关系，在一项大型 agent 研究中，更多思考在 36 个设置中的 21 个反而降低了准确率，因此供应商的“高努力”数字甚至不能与同一模型在独立默认努力运行下的结果比较。

**`2026` 年 9 月的新基准让这一点变得具体。** 同一 GPT-`6` Astra 在 ARC Prize 供应商中立的 ARC-AGI-3 评测框架下得分 `62.7%`，在使用 OpenAI 自身上下文管理功能、于请求间传递不透明推理状态的 Provider Adapter 框架下为 `99.9%`。评分指标对数字的影响与模型一样大：OSWorld `2.1` 顶部同一行的二元完成率为 `44.33%`、部分得分为 `77.67%`；Agents' Last Exam 顶部同一行通过率为 `38.2%`、得分为 `63.2`。有些标题数字甚至不再属于一组固定权重。Anthropic 在启用生产防护的状态下评测 Claude Opus `5.5`；防护介入时，网络安全任务由 Claude Opus `4.8` 完成，生物学和前沿 LLM 开发任务由 Claude Opus `5` 完成（Zapier AutomationBench 未使用回退，因此介入算失败）。Artificial Analysis 现将此类条目标记为“with fallback”。该分数衡量的是路由系统，对它做回归测试时须像固定框架和 effort 一样固定回退状态。

比较两个数字前，应固定以下各项：

| 固定项 | 影响数字的原因 | `2026` 年示例 |
|--------|----------------|---------------|
| 基准版本 | 主版本会退役和修复任务，成绩不能沿用 | Terminal-Bench `3.0` 到 `4.0`：删除 `8` 项、修复 `19` 项 |
| 评测框架与脚手架 | 工具、保留的状态和压缩改变所测能力 | ARC-AGI-3：同一模型 `62.7%` 对 `99.9%` |
| effort 级别 | 并非单调，实验室报告最佳设置 | Terminal-Bench `4.0`：Fable `5.1` high 为 `54.55%`、max 为 `57.88%` |
| 指标 | 二元与部分得分、通过率与评分不同 | OSWorld `2.1`：同一行二元 `44.33%`、部分 `77.67%` |
| 运行方 | 供应商使用自己找到的最佳配置 | Opus `5` 在 OSWorld `2.1`：Anthropic 自报的 `74.0%` 部分得分与榜单任何一行都不匹配 |
| 回退状态 | 安全防护路由把部分任务交给其他模型 | Artificial Analysis 上标记“with fallback”的 Opus `5.5` |
| 每任务成本 | 相同成绩的成本可能相差数倍 | DeepSWE v`1.1`：同为 `74%`，每任务成本从 `$2.36` 到 `$11.84` |

**`2026` 年年中还浮现出第三类误差来源：基准自身的测试。** 一项对 `15` 个代理基准中 `2,385` 条轨迹的审计发现，其中两个基准约 `67%` 的轨迹存在奖励黑客行为或答案暴露：代理通过找回公开解法、读取评测工件，或利用无效评分路径来取得结果，而非真正解决任务。另一项 SWE-bench Verified 审计指出，未解决样例中有相当一部分测试存在缺陷。9 月的数据说明这种问题如何随能力扩展：一项对 `3,810` 条通过轨迹的审计发现，在匹配任务上，SWE-Bench Pro v`1.0` 中不应获得的通过从 Opus `4.7` 的 `24%` 升至 Fable `5` 的 `73%`（arXiv `2609.34262`）；METR 调查 OpenAI 7 月的网络安全评测，发现约 `7%` 的转录存在工具调用伪造，外部估计 `30%` 至 `40%` 的目标本来就无法按预期被利用。分数上升可能意味着代理更擅长作弊。实践规则是：分数跃升时应核查是能力提升还是协议泄漏，并优先选择公布有效性审计与重评结果的基准。加固清单见[评测代理系统](../07-agentic-systems/10-evaluating-agentic-systems.md)。

**污染检测如今也有了关于自身局限的理论。** `2026` 年 8 月发表的一项形式化研究表明，可检测性随污染比例、已见与未见项目之间的行为差距以及样本量平方根变化。对实践者而言，其结论是：小规模审计得出的“没有污染证据”存在歧义，它既可能表示基准测试干净，也可能表示检验效力不足；因此，污染结论只有在说明统计功效计算时才有意义。

### 排行榜幻觉

对 LMArena 的核心批评（Cohere 等，对约 2M 场对战、243 个模型的审计）发现了四个问题：供应商私下测试许多变体，只发布最好的（Meta 在 Llama-4 前测试了 27 个变体），这违反了 Elo 数学背后的无偏抽样假设；闭源供应商获得的对战数据远多于开源模型；你可以针对 Arena 分布训练，从而获得大量胜率增益；悄悄弃用的模型会扭曲排名。LMArena 的回应质疑了影响幅度（他们估计私下测试带来的提升约为 11 Elo，并会随着新投票累积而衰减），并指出过拟合数字是在静态代理上测得的，而不是实时人类榜。应把这呈现为**有争议但有证据支持。**

无论如何，实践建议都是一样的：把 Arena Elo 视为**通用聊天偏好**的度量，而不是正确性、事实性或困难推理的度量；始终使用风格控制榜（Arena 会奖励更长、更漂亮的回答）；阅读置信区间（前 ~15 名在统计上接近并列）；并把它作为三类信号之一，而不要单独使用。

### 基准测试到生产的差距

公开分数只有在三个条件同时成立时，才会预测你的生产表现：基准考察的任务与你的任务相似，测试集没有污染，并且基准尚未饱和。实践中这三点很少同时成立。基准分数的主成分分析发现，单一“通用能力”因子只能解释约 `50%` 的方差；剩余部分是模型家族特性和噪声，因此两个通用能力相当的模型在*你的*任务上可能表现差异很大。高 GPQA 不保证你的领域表现。`2026` 年 9 月的一项构念效度研究（arXiv `2609.08812`，跨 `53` 个模型的 `56` 个基准）进一步发现：声称衡量相同概念的能力基准，其相互相关性与衡量*不同*概念的基准大致相当；得分格式等设计特征，有时比共同概念更能预测相关性。基准名称并不保证它真正衡量什么。

在上述主成分分析中，GPQA-Diamond 和 SWE-bench Verified（还有 Aider Polyglot 与 AIME 风格集合）最能反映通用能力，但两者此后都已饱和，正说明代理指标会过期。每个实践者都会得出这个结论：**为自己的决策，在自己的数据上构建评测。** 构建按功能、场景和用户画像划分的金标集；使用经领域专家校准的二元 LLM 裁判（以精确率和召回率衡量，而非原始一致率）；并把能力与成本一起衡量。如今有些公开榜单会公布每任务或每次运行成本（Terminal-Bench `4.0`、DeepSWE、Agents' Last Exam、ARC Prize、Arena 的代理类别），可见成绩接近时成本可能相差数倍，但它们都没有按你的流量、缓存命中率和 effort 设置定价。参见 [LLM 评测](01-llm-evaluation.md)和[白板练习](../00-interview-prep/04-whiteboard-exercises.md)中的评测流水线练习。

### 复合指数

由于任何单一基准测试都会在一两年内饱和，领域会用加权复合指标对前沿模型排名；当组件达到满分时，它们仍能保持区分力，并能抵抗对单个测试的过拟合：

- **Artificial Analysis 智能指数**会在组件饱和时更换版本，**不同版本的分数不可比较**。v`4.3` 于 `2026` 年 9 月 7 日推出（当前修订版为 v`4.3.2`），包含 `10` 项评测，并向代理工作倾斜：

  | 类别 | 权重 | 组成 |
  |------|------|------|
  | 代理 | `30%` | AA-Briefcase v`1.1`（`15%`）、GDPval-AA v`2.1`（`10%`）、AutomationBench-AA（`5%`） |
  | 编码 | `20%` | Terminal-Bench `4.0`（`10%`）、SciCode（`10%`） |
  | 通用 | `30%` | AA-Omniscience（`15%`：准确率 `10%`、非幻觉 `5%`）、GDP.pdf（`10%`）、AA-LCR v`1.1`（`5%`） |
  | 科学推理 | `20%` | HLE（`10%`）、CritPt（`10%`） |

  已移入历史指标：GPQA Diamond、AIME `2025`、MATH-`500`、MMLU-Pro、LiveCodeBench、tau2 Telecom、tau3-Banking、Terminal-Bench `2.1` 和 Terminal-Bench Hard。10 月初榜单为：Claude Opus `5.5`（max、带回退）`58`，Claude Sonnet `5.5`（max、带回退）`56`；在 Opus `5.5` 的其他 effort 设置之后，Claude Fable `5.1`（max、带回退）、GPT-`6` Astra（max）、Gemini `4` Argon（high）均为 `53`。Argon 于 9 月 30 日宣布有限度推出，尚未进入 Gemini API。9 月初的报道引用了旧版 v`4.3` 之前的指数：Fable `5.1` 为 `66`、Astra 为 `61`。这属于不同指数，不能放进同一张表比较。
- **Epoch Capability Index（ECI，Epoch 能力指数）** 在约 1,000+ 项评测上拟合 item-response-theory（项目反应理论）模型，从统计上推断每个基准测试的难度，因此模型在*更难*的基准测试上表现好会获得更高分。
- **HAL（Holistic Agent Leaderboard，普林斯顿整体 Agent 排行榜）** 是面向 agent 的、具备成本意识的复合指标：它同时评分准确率*和*美元成本，在各模型上运行固定 harness，并用日志分析发现 agent 走捷径（从 arXiv 抓答案而不是解题）和 eval bug。它存在的原因是，以 10 倍成本换来 1% 的准确率提升并不算胜利。

复合指标适合回答“哪个模型总体最好”，但它们仍会继承组件的缺陷，因此要看清它们聚合了什么。

## 实用清单

当你阅读任何基准测试声明时：

1. **阅读评测框架，而不只是数字。** 要求提供基准版本、脚手架、工具访问、effort 级别、输出 token 上限、评分指标（二元或部分）、运行方和回退状态（见[框架与脚手架方差](#harness-与脚手架方差)的固定项表）。裸百分比无法解释。
2. **检查置信区间。** 忽略噪声带内的差异。SWE-bench Verified 只有 `500` 道题（每题约 `0.2%`）；Terminal-Bench `4.0` 只有 `66` 项任务，Anthropic 自报的 Opus `5.5` 数字带有 ±`2.6` 个百分点的标准误；Arena 中低于约 `15–20` Elo 的差距都是噪声。在配置匹配前，不信任低于约 `3` 个百分点的差距。对于持续更新的榜单，基于 e-process 的随时有效检验（arXiv `2609.32248`）能在避免反复查看固定样本置信区间问题的同时回答“差距是真的吗”。
3. **优先选择时间门控、私有、留出或委托编写的测试集。** 对静态公开集（MMLU、HumanEval、GSM8K、SWE-Bench Pro 公开子集），假设存在污染，并折扣绝对数值。
4. **绝不要跨 harness 或自报分数比较。** 只有同一 harness 下的数字才可比较。
5. **核对模型名称。** 如果某个前沿分数被归因于找不到一手来源的模型，它很可能是编造的。截至 `2026` 年 10 月 1 日已确认的前沿模型名称：Claude Fable `5.1` 与 Mythos `5.1`、Opus `5.5`、Sonnet `5.5`、Haiku `4.5`（Fable `5`、Opus `5` 和 Sonnet `5` 仍可用）；GPT-`6` Astra、GPT-`6` Sol、GPT-`6` Luna、GPT-`6.1` Sol，以及 GPT-`5.6` Sol、Terra、Luna 一代；Gemini `3.8` Flash 和 `gemini-3.1-pro-preview`，Gemini `4` Argon 已于 9 月 30 日宣布但尚未进入 Gemini API；Grok `4.7`；Muse Spark `1.3`；开放权重模型 MiMo-V`2.6`-Pro、GLM-`5.3`、Kimi K`3`、DeepSeek V`4.1`-Flash 和 V`4`-Pro，以及 Qwen`3.8`。截至该日期尚未交付、无论聚合网站如何声称的名称：GPT-`6` Terra、Gemini `3.5` Pro、Claude Haiku `5.5`，以及从不存在的 Llama `4` `8B/70B/405B`。聚合网站还会发布与基准官方榜单矛盾的成绩，例如“Gemini `3` Pro 在 SWE-bench Pro 上 `84.8%`”；应核查一手榜单。
6. **在信任排名前，三角验证三类信号**：静态学术 eval、人类偏好 arena，以及 agentic suite（智能体套件）。
7. **对你的决策，在你的数据上构建 eval。** 公开分数很少能预测你的领域。排行榜告诉你该把谁列入候选；你的黄金集告诉你该把谁上线。

## 2026 中哪些基准测试重要

用于判断**前沿通用能力**：HLE-Diamond（注明有无工具）、HLE 与 CritPt（注意标签错误）、ARC-AGI-`2` 与 ARC-AGI-`3`（注明评测框架），以及复合指数（Artificial Analysis 智能指数 v`4.3.2`、Epoch ECI）。排名时忽略 MMLU、MMLU-Pro、HellaSwag、ARC-Challenge，如今也应忽略 GPQA-Diamond。

用于**编码和代理**：SWE-Bench Pro v`2` 私有集、DeepSWE 和抗污染的实时变体（SWE-rebench、SWE-bench-Live）用于实际排序；Terminal-Bench `4.0` 用于终端工作，Terminal-Bench-Science 用于代理式科学工作流（两者的供应商排名不同）；tau3-bench 用于工具使用可靠性（关注 pass^k）；OSWorld `2.x` 的**二元完成**用于计算机操作；Agents' Last Exam 用于按工件评分的专业工作；HAL 或这些榜单上的成本列用于考虑成本。SWE-bench Verified 与 SWE-Bench Pro 公开子集最多只能作层级过滤器。排名时忽略 HumanEval/MBPP 和 OSWorld-Verified。

用于**深度研究**：选择 BrowseComp-Plus 等控制语料库的评测；BrowseComp 本身已饱和。

用于 **Long Context（长上下文）**：优先看 RULER 和 Fiction.LiveBench，而不是 NIAH；设计时关注有效上下文，而不是宣传中的上下文长度。

用于 **Factuality（事实性）**：SimpleQA 用于闭卷幻觉评估，FACTS Grounding 用于 RAG（检索增强生成）忠实度；记住，更强的能力并不意味着更高的事实性。

用于**嵌入和检索**：选择将公开数据集与由维护者评测的私有留出集结合的 RTEB，而非只看 MTEB 排名；参见[嵌入模型](../06-retrieval-systems/03-embedding-models.md)。

用于**偏好**：采用带置信区间的风格控制 Arena Elo（将首日 AutoEval 成绩视为预测），或将 Arena-Hard-Auto v`2` 作为可复现代理指标。

至于 **你的产品**：以上都不够。构建你自己的黄金集和评审器。这个方向的前沿研究正在快速发展（智能体可靠性科学、声明级忠实度评估、模型能检测自己正在被测试的评测感知能力）；见 [研究雷达](../RESEARCH-RADAR.md)。

## 面试题

### 问：某供应商说他们的模型在 SWE-bench Verified 上得分 90%。在相信它能预测你的编码智能体质量之前，你会问哪些问题？

**优秀回答：**
首先看评测框架：使用了哪个代理脚手架、哪些工具、什么 effort 级别、输出 token 上限是多少？相同权重仅因脚手架不同就会波动 `10–20` 个百分点，供应商通常报告最佳框架下的数字，因此这 `90%` 不能与其他模型发布的数字直接比较。其次看污染：SWE-bench Verified 部分受到污染（OpenAI 发现可从任务 ID 复现解法，仓库扰动研究也表明模型依赖记忆化的仓库线索），所以我会要求看抗污染集：SWE-Bench Pro v`2` 私有子集（Opus `5` 在其中为 `81.6%`，公开子集为 `99.4%`）、DeepSWE 的委托编写任务，或 SWE-rebench。第三看置信区间：它只有 `500` 个问题，所以几个百分点可能只是噪声。第四也是最重要的，看生产差距：即使 SWE-bench 数字干净，也只有当我的任务类似 GitHub issue 解决时才可能预测我的代码库表现。我会用公开数字做入围筛选，最终用来自我们仓库真实工单的金标集，由校准过的裁判评分，并结合成本做决策。

### 问：为什么 MMLU 和 HumanEval 这类基准测试已经不再适合用于前沿模型排名？它们被什么取代了？

**优秀回答：**
它们已经饱和：前沿模型在 MMLU 上集中在 `88–90%` 以上，在 HumanEval 上达到 `90%+`，因此差异落在提示词措辞噪声范围内。它们也很小且公开，容易污染；重新推导 HumanEval 问题会让分数下降约 `39%`。而且它们衡量的构念过于简单：单函数的文档字符串到代码任务无法预测真实工程能力，这就是为什么同样在 HumanEval 上表现优异的模型，在 SWE-bench 刚推出时得分低于 `2%`。该领域用更难的后继基准（MMLU、MMLU-Pro、HLE、HLE-Diamond）、抗污染的时间门控或委托编写基准（LiveCodeBench、SWE-rebench、DeepSWE）、代理和仓库规模基准（SWE-Bench Pro、Terminal-Bench、tau3-bench、OSWorld `2.x`），以及组件饱和后仍能区分的复合指数取代了它们。`2026` 年的挑战是后继基准也会迅速换代：Terminal-Bench `3.0` 只用了约四周，因此我引用的每个分数都会附版本。

### 问：在为聊天产品选择模型时，你会如何负责任地使用 Arena（原 LMArena）Elo？

**优秀回答：**
把它作为通用聊天偏好的一个信号，不把它当作正确性或推理能力的度量。我会阅读风格控制榜单，因为原始 Arena 会奖励更长、格式更好的答案，不管它是否正确；也会阅读置信区间，因为前十几名模型在统计上大致接近，差距在约 `15–20` Elo 以内。我还会对排行榜幻觉效应打折：提供方会私下测试许多变体并发布最好的那个，刚登顶的条目可能部分来自多次尝试后的运气。对本周发布的模型，我会检查其成绩是 AutoEval 奖励模型的预测，还是已经累积的人工投票；投票到来前仅将其视为预测。然后结合客观基准和代理套件交叉验证，最终在自己的偏好数据上确认，因为 Arena 的提示词不是用户的提示词。

### 问：发布文章声称 ARC-AGI-3 为 `99.9%`，OSWorld `2.1` 为 `81.8%`。你如何解读？

**优秀回答：**
比较前先确定测量对象。ARC-AGI-3 的标题数字取决于评测框架：ARC Prize 核验 GPT-`6` Astra 在使用 OpenAI 上下文管理功能、于请求间保留不透明推理状态的 Provider Adapter 框架下为 `99.9%`；同一模型、同一测试集在供应商中立的 Standard 框架下为 `62.7%`。所以我要问框架、effort 和成本（这两次运行分别为 `$18,817` 与 `$26,098`）。对 OSWorld，我要问指标：`81.8%` 是 Anthropic 的 Opus `5.5` 部分得分，而基准的主要指标是二元完成；榜单最佳一行在该指标上为 `44.33%`（Opus `5`、max effort）。还要问运行方是谁（Anthropic 自报的 Opus `5` `74.0%` 部分得分与榜单任何一行不符），以及安全防护是否把部分任务路由给回退模型，Anthropic 的 Opus `5.5` 评测就发生了这种路由。实际规划会采用独立运行的二元成绩、限定到与我相似的任务，并在自己的评测集上确认。部分得分说明代理走了多远；只有二元成绩说明工作有多常完成。
