## 在“数据墙”之后：合成转向

开放模型公开的预训练预算已达到 15T 至 36T+ token（Llama 4 的混合数据超过 30T），而高质量且来源合法的人类文本供应并未以相同速度增长。封闭实验室不披露总量。

**现实是：** 后训练数据集如今大多由模型生成（推理轨迹、改写、经验证的解答），预训练中的合成数据占比也在上升：微软的 Phi-4 报告将 **40% 的预训练 token** 分配给合成数据。多数实验室不公开数据配比，因此任何全行业通用的单一占比都只能视为猜测。

| 来源 | 人类数据 | 合成数据 |
|--------|------------|----------------|
| **体量** | 固定（有限） | 无限 |
| **质量** | 可变（有噪声） | 可控（已净化） |
| **成本** | 高（人工标注者） | 低（推理/GPU） |
| **偏差** | 互联网的镜像 | 可手工平衡 |

## Evol-Instruct 模式

Evol-Instruct 是一个递归过程：LLM 接收一个简单指令，并把它演化为一个更复杂的指令。

**演化方向（据 WizardLM 论文）：**
1. **纵向深化**：添加约束、深化问题、使其更具体，或要求更多推理步骤。
2. **横向扩展**：将指令变为同一领域中新的、更少见的指令，以扩大主题覆盖面。
3. **淘汰**：在失败的演化结果进入训练集前将其丢弃，例如没有新信息、无法回答，或只是复制了待演化的提示。

```python
# Simple Instruction: "Write a function to add two numbers."
# Evolved Instruction: "Write a thread-safe Python class that performs 
# matrix addition with error handling and unit tests, adhering to PEP8."
```

## 宪法式 AI 与 AI 反馈（RLAIF）

由 Anthropic 开发，并在整个行业中被广泛采用，RLAIF 使用一份“宪法”（一组规则）来指导模型评估并改进自己的数据。

**流程：**
1. **提出**：模型 A 生成一个回答。  
2. **批评**：同一个模型或另一个评判模型依照宪法原则识别缺陷。
3. **修订**：模型 A 基于批评生成更好的版本。  
4. **训练**：最终的（Prompt，Revise）对被加入 SFT 集。

## 可验证的合成数据

合成数据最大的风险是 **模型坍塌**（Model Collapse，即模型学习到自己的错误）。  
**标准解决办法**：聚焦那些无需 LLM 就能验证“真值”的领域。

- **数学**：使用形式化验证（Lean/Isabelle）或 Python 执行来验证答案。形式化检查如今可以处理非常长的机器生成结果：据 Anthropic 报告，其内部模型在 11 天内用 Lean 形式化了费马大定理，生成约 13M 行内容，并由 Lean 验证结果（厂商报告，经 Kevin Buzzard 审阅）。
- **代码**：让生成的代码在测试用例上运行（单元测试）。
- **RAG**：使用“黄金上下文”生成问题，使答案明确写在文本中。

## 去偏与多样性

合成数据用于“填补”人类数据中的空白。
- **语言**：通过翻译概念模板，为低资源语言（例如斯瓦希里语、马拉地语）生成高质量文本。
- **逻辑**：创建 1,000,000 个特定逻辑谬误的变体，以“加固”模型对它的抵抗能力。

## 来源与许可

每一条合成数据都继承生成它的模型所附带的义务。

- **教师模型条款**：封闭模型的条款通常禁止使用输出训练竞争模型，厂商如今也会识别大批量收集思维链的流量（见[知识蒸馏](05-knowledge-distillation.md#蒸馏威胁-通过-api-提取模型能力)）。开放教师模型的条款各异：MIT 和 Apache 2.0 较宽松；定制许可证（Kimi K3、Qwen Community 1.0）对托管产品附加条件。
- **来源链跨越国界**：NVIDIA 的竞赛编程研究模型在一次非官方运行中超过 IOI 2026 金牌门槛；它使用从 Z.ai 的 GLM-5.2 蒸馏的 477,642 条轨迹训练。GLM-5.2 的 MIT 许可证允许这样做，但合规团队仍会询问哪些模型处理过这些数据。
- **逐条记录**：生成模型及其版本、许可证、提示模板、接纳该条数据的验证器，以及它所源自的种子语料库。法院正将合法训练与非法获取源材料区别对待，因此种子数据的获取记录与生成模型的许可证同样重要。

## 面试题

### Q: 在使用合成数据训练时，“模型坍塌”有什么风险？

**强回答：**  
模型坍塌发生在模型使用其早期版本生成的数据进行训练时。因为模型的分布比真实世界更窄（它对某些词和模式存在偏好/偏差），训练循环就会变成错误和乏味内容的“正反馈循环”。标准缓解方法包括：
1. 混入 5-20%“金牌”人类认证数据。  
2. 使用“可验证”的奖励（数学/代码），让错误永远不会被学进去。  
3. 使用更强大的“教师”模型为“学生”模型生成数据。

### Q: 你如何确保一个 1000 万行合成数据集的*质量*？

**强回答：**  
我们使用一个 **多阶段过滤流水线**：  
1. **语义去重**：使用嵌入向量移除近乎相同的簇。  
2. **LLM 作为裁判**：抽样 1% 的数据，先用少量人工标注数据校准更强的评判模型，再让它从逻辑和安全性方面打分。
3. **困惑度过滤**：使用小模型计算文本的困惑度。如果太高（胡言乱语）或太低（重复/过于简单），就丢弃。  
4. **可验证执行**：如果数据包含代码或数学内容，必须通过本地编译器/解释器检查。
