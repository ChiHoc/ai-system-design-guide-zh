# 知识蒸馏

知识蒸馏（Knowledge Distillation）是将一个大型、复杂模型（“教师”）的智能迁移到一个更小、更高效模型（“学生”）的过程。它是当今小型开放权重模型（open-weight models）表现远超其参数规模的重要原因。

## 教师-学生范式

许多小模型并非只用原始网页数据训练，还会使用大得多的模型提供的输出、logit 或推理轨迹。已有文档记载的案例来自开放模型：

- **Gemma 2**（2B 和 9B）以及**所有 Gemma 3 规模**都在预训练中使用了更大教师模型的蒸馏。
- **Llama 3.2 1B/3B** 在预训练中加入了 Llama 3.1 8B 和 70B 的 logit；**Llama 4 Maverick** 则与未发布的 Llama 4 Behemoth 进行了协同蒸馏。
- **DeepSeek-R1 蒸馏检查点**是在 R1 生成的约 800K 样本上微调得到的 Qwen 和 Llama 模型。
- **NVIDIA 的 Nemotron-Labs 竞赛编程模型**（2026 年 9 月）在一次非官方运行中超过 IOI 2026 金牌门槛；它使用从 Z.ai 以 MIT 许可发布的 GLM-5.2 蒸馏而来的 477,642 条推理轨迹训练。教师来源如今跨越厂商和国界，因此要记录来源。

封闭实验室不公布小模型的训练配方。“Claude Haiku 由 Opus 蒸馏而来”或“Gemini Flash 由 Pro 蒸馏而来”或许合理，但没有文档证实。

| 模型 | 角色 | 智能来源 |
|-------|------|---------------------|
| **教师** | 大型（100B+ 参数，通常为 MoE） | 前沿规模预训练（公开的 token 数为 15T-36T+）及后训练 |
| **学生** | 小型（1B - 30B 参数） | 教师筛选后的输出、logit 或推理轨迹 |

## 蒸馏如何工作

### 1. 硬标签蒸馏
学生从教师的最终预测中学习（例如，对某个问题的答案）。

### 2. 软标签蒸馏（温度缩放，Temperature Scaling）
学生从教师的**概率分布**（Logits）中学习。这种信息丰富得多，因为它不仅告诉学生正确答案，还告诉它哪些错误答案“几乎”正确。

```python
# Distillation Loss (KL Divergence):
Loss = KL_Div(Teacher_Logits / T, Student_Logits / T)
```
*其中 T 表示温度（通常为 2.0 - 5.0）。*

### 3. 在线策略蒸馏
学生采样自己的续写，由教师为每个 token 评分，结合了 RL 的在线策略相关性和 SFT 的密集信号。这在 2025-2026 年成为较低成本训练推理模型的热门路径，但其作用机制如今存在争议：一篇 2026 年 8 月的论文（arXiv:2608.31046，9 月修订，仅一组研究者的结果）报告称，教师信号噪声很大，大部分收益来自抑制低概率 token；一种不依赖教师的方法达到了并超过了它的效果。在为大教师模型付费之前，应先运行无教师基线。详见 [RLVR 与推理模型](08-rlvr-and-reasoning-models.md#蒸馏-更便宜的路径)。

## 特征蒸馏与输出蒸馏

### 输出蒸馏（标准方式）
学生匹配教师的文本响应。
- **优点**：可通过 API 轻松实现。
- **缺点**：只学习行为表层模式。封闭 API 越来越多地返回摘要化或加密的推理内容，通常无法取得原始思维链进行蒸馏。
- **平台风险**：厂商托管的蒸馏流水线正在收缩。OpenAI 从存储的生成结果到微调的路径依赖两项正在停止的产品：Evals 于 2026 年 10 月 31 日变为只读，并于 11 月 30 日关闭；活跃客户从 2027 年 1 月 6 日起不能创建新的自助微调作业（见[微调策略](02-fine-tuning-strategies.md#微调的实施平台)）。应将数据集、评估套件和学生模型训练保留在自己可控的基础设施上。

### 特征/隐藏状态蒸馏
学生匹配教师内部的**隐藏状态**（Hidden States，向量表示）。
- **要求**：你需要能够访问教师的权重（开放权重，Open Weights）。
- **优点**：学生学习到教师的“内部概念地图”，从而显著提升推理深度。

## 通过拒绝采样进行自蒸馏

**一种核心的推理训练技术。** 文献将其称为拒绝采样微调、专家迭代或 STaR。模型无需新增人工数据即可改进：

1. **生成**：模型为一个困难的数学/代码问题生成多个候选解。
2. **验证**：基于规则的系统（编译器、测试套件、计算器、证明检查器）只保留正确解。
3. **蒸馏**：模型在导向正确解的思维链上进行微调。

**结果**：模型通过只保留高质量推理路径来“蒸馏自己”。DeepSeek-R1 记载了这一环节：RL 阶段后，它通过拒绝采样收集了约 600K 条经验证的推理样本（另有约 200K 条非推理样本），用于下一轮 SFT。OpenAI 和 Anthropic 尚未公开各自的训练配方。同一思路的 RL 版本见 [RLVR 与推理模型](08-rlvr-and-reasoning-models.md)。

## 量化感知蒸馏

标准量化（例如从 16 位到 4 位）会带来轻微的准确率下降。
**解决办法**：在量化过程中使用知识蒸馏。16 位模型充当教师，引导 4 位模型尽量减小误差。结合量化感知训练，厂商便能发布质量接近 16 位模型的低位宽版本，例如 Google 使用 QAT 的 int4 Gemma 版本。参见[量化深入解析](07-quantization-deep-dive.md)。

## 蒸馏威胁：通过 API 提取模型能力

如果通过 API 提供模型服务，就会有人尝试蒸馏它。如今已有大规模记录：

- Anthropic 于 2026 年 2 月披露，三个中国实验室的蒸馏活动通过约 24,000 个欺诈账户进行了超过 16M 次交互。代理服务运行“hydra cluster”账户网络（其中一个网络同时管理 20,000+ 个账户）；提示要求 Claude 写出完成回答背后的推理，以收集思维链训练数据。
- Anthropic 2026 年 9 月的威胁报告（9 月 10 日获报道）描述了五项已归因活动，涉及近 200M 次交互；规模最大的一项在三个月内通过超过 3,500 个账户进行了超过 151M 次交互。
- 8 月，研究者指出，若几个供应商对同一模型家族共用一把加密密钥，加密的推理块就可能跨模型重放；供应商随后修复了漏洞。
- 隐藏推理也会通过其他方式泄漏：一篇 2026 年 9 月的论文（arXiv:2609.26637）通过标准 API 功能注册简单自定义工具，从包括 GPT-6 Astra 在内的前沿模型提取了隐藏推理。

**对 API 运营方的设计启示：**调整请求速率形态、按账户识别行为特征（包括检测诱导输出思维链的提示）、加强账户验证、共享威胁情报，并限制暴露的推理内容；随后对所有可能暴露推理的路径（工具调用、结构化输出、重放的推理块）进行红队测试，而不能只检查回答文本。这些对策也解释了 API 使用者会遇到的几项变化：摘要化的思考内容，以及绑定到产生它的模型和对话的思考块（Claude Fable 5.1、Opus 5.5 和 Sonnet 5.5；Sonnet 5.5 的块还会绑定到产生它的账户）。

## 面试题

### 问：为什么蒸馏后的 8B 模型会比用相同 token 从零训练的 8B 模型更好？

**强答案：**
从零训练（预训练，Pretraining）原始网页数据噪声很大；模型会消耗大量容量去学会如何穿过这些噪声。蒸馏模型则是在“净化过”的课程上训练的。教师模型充当高质量过滤器，提供结构化逻辑、清晰解释和更干净的语言分布。本质上，教师通过其 logit 分布提供“提示”，告诉学生语言中哪些特征最重要、最值得学习。

### 问：将封闭 API 模型蒸馏成开放权重学生模型有哪些风险？

**强答案：**
1. **模型坍塌**：如果学生只看到教师输出，它可能会失去创造性或多样性知识的“长尾”部分，只学到教师狭窄的偏见。
2. **许可证违规**：大多数专有模型（OpenAI、Anthropic）都包含禁止将其输出用于训练“竞争性”模型的条款。对于企业来说，使用 API 输出蒸馏自有模型，这是重大的法律风险。
3. **检测与执行**：厂商如今主动识别蒸馏流量。Anthropic 的 2026 年报告提到会识别诱导思维链的提示特征并封禁账户网络，因此依赖大量教师调用的流水线可能在项目中途被切断。
4. **可获得的信号比预期少**：封闭 API 提供的是摘要化或加密的推理，而不是原始思维链或 logit，因此只能进行输出蒸馏。
5. **语言模仿**：学生可能学会“听起来”很自信（像教师一样），却没有相同的逻辑深度，最终导致看起来很肯定但实际上错误的幻觉。

更稳妥的做法是使用许可证宽松（MIT 或 Apache 2.0）的开放权重教师模型，并为每条训练数据记录教师身份及其许可证。
